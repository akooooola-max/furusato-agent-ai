1本提案の位置づけ

7月31日に頂戴した「ふるさと理事長AI」構想（組織図・構想資料）への、実装のご提案です。

先に結論を申し上げます。構想の骨格は、変える必要がありません。5室＋本部直属2機能という編成、加算を攻め（戦略室）と守り（コンプライアンス室）で分離する設計、検算役→内部監査室→理事長という統制ライン。いずれもAIによる経営組織の設計として、そのまま実装に耐えるものです。

本提案がお示しするのは、次の4点です。

  1. その組織をClaude Code上でどういう形にするか（役割定義書9項目による実装）
  2. 統制ラインをどう実際に効かせるか（検算役5項目＋人間の最終確認＋稟議）
  3. ナレッジをどう積み上げるか（選別・承認・版管理・廃止管理）
  4. どの順番で立ち上げるか（試作とサンプル検証から始める段階ロードマップ）

2設計の4原則

構想資料の「実装の考え方」と同じ方向です。実装にあたり、次の4つを憲法（CLAUDE.md）に固定します。

原則1：番人箱は渡さない
利用者の要配慮情報・職員の人事給与情報・符号台帳（符号と実名の対応表）は、AIに触れさせるフォルダに置きません。AI社員が扱うのは、公開情報（制度・報酬・統計）と、符号化・前処理済みのデータだけです。既に法人版マニュアルで整備されている線引きを、そのまま経営組織にも適用します。
原則2：設計は全体、着手は1室ずつ
構想資料の結びの通りです。7室を一斉に立ち上げず、1室ずつ動かして、動いた室の型を次の室に写します。最初の1室が組織全体の雛形になります。
原則3：AIは起案まで、決裁は人
AI社員の仕事は「調べる・分析する・起案する」までとし、外に出る操作・確定する操作（送信・公表・提出・契約）の直前には、必ず本文を提示して理事長の承認を取ることを憲法に明記します。構想にある稟議承認を、そのまま憲法の条文にする形です。
原則4：載せる前に、サービスの条件を確認する
番人箱を渡さないという線引きに加えて、使うAIサービス側の条件を法人として確認し、記録に残してから運用を始めます。確認するのは次の6点です。
確認項目何を確かめるか
契約形態法人契約か個人契約か。管理者は誰か
学習利用入力した内容がモデルの学習に使われない設定・契約になっているか
保存期間会話や成果物がサービス側に何日残るか
権限誰がどのフォルダ・どの機能にアクセスできるか
ログ誰がいつ何をしたかの記録が残り、法人側で確認できるか
削除方法会話・データを削除する手順と、削除が完了したことを確認する方法
確認結果は法人の記録として1枚にまとめて保管し、契約条件が変わった場合は運用も見直すことを前提とします。

3実装の形 ― AI社員の実体は「部署ごとの役割定義書（CLAUDE.md）」

北島様が既に作られたマニュアルの三本柱（①憲法 ②番地を振ったフォルダ ③再開の記録）を、そのまま組織に拡張します。AI社員1人＝部署フォルダ1つ＋その部署の役割定義書（CLAUDE.md）1枚です。

furusato-ai/ ├── CLAUDE.md ← 憲法（4原則・番人箱・稟議ルール・全室共通の型） ├── 00_稟議箱/ ← 理事長の承認待ち成果物が集まる場所 ├── 10_戦略室/ │ ├── 外部環境分析部/CLAUDE.md │ ├── 加算戦略部/CLAUDE.md │ └── … ├── 20_コンプライアンス室/ │ └── 加算要件管理部/CLAUDE.md ├── 90_内部監査室/CLAUDE.md ← 独立。他室の成果物を横断点検 ├── 98_ナレッジ/ ← 承認済みナレッジのみ（版・承認日つき） └── 99_記録/ ← 各室の作業記録（再開の仕組み）

各部署の役割定義書（CLAUDE.md）には、次の9項目を書きます。AI社員に何をさせるかだけでなく、人間側の責任者・根拠・検証・記録・評価・報告先まで一枚に含めるのが要点です。

項目例（加算戦略部の場合）
① 役割加算を「収益」と「アウトカム」の両立で設計する
② 人間側の責任者事務長（この部署の成果物に責任を負う人間を必ず1名置く）
③ 扱ってよい情報・根拠資料厚労省・自治体の一次情報（URL・発出日・適用日を明記）、符号化済みの算定実績
④ 成果物の型加算シナリオ試算表（出典URL／適用日／作成日／作成者の4欄を必須とする）
⑤ 検証・承認検算役の点検 → 人間の責任者による最終確認 → 理事長の稟議承認（3段階すべてを通す）
⑥ ログ・版管理作業ログは99_記録へ。成果物はv1・v2…と版を付け、差し替え時も旧版を残す
⑦ 評価指標何をもって成果とするか（例：算定漏れ0件／根拠URL添付率100％／要件変更の見落とし0件）
⑧ 報告先加算戦略部 → 事務長（責任者）→ 戦略室 → 稟議箱（理事長）
⑨ 禁止事項番人箱・符号台帳に触れない／要件の断定をしない（一次情報照合を必須とする）

②〜⑧を入れる理由は、AIの成果物には必ず人間の持ち主が要るためです。責任者・根拠・検証・記録・評価・報告先が定義書に書かれていれば、担当者が代わっても運用が止まりません。

この形の利点は、部署の増減が「フォルダとファイルの増減」だけで済むことです。構想の「全部署フル配置ではなく、部署の重さで増減する」を、そのまま実現できます。

4統制ラインの実装 ― 検算役・内部監査室・稟議

構想の統制フロー「成果物 → 検算役 → 内部監査室 → 理事長」を、次のように実装します。

  • 検算役：各部署の成果物テンプレートに検算チェックリストを埋め込み、作った本人とは別のセッションのAIに点検させます。作る係と検算する係を同じ会話にしないことが要点です。点検項目は次の5つとします。
    1. 一次資料に当たっているか（厚労省・自治体の原文か。要約サイトや記憶に頼っていないか）
    2. 適用日が明示されているか（発出日と、いつから適用される要件かを区別しているか）
    3. 根拠が示されているか（数字の一つひとつに出典URLと計算根拠が付いているか）
    4. 番人箱に触れていないか
    5. 要件を断定していないか（「一次情報での確認が必要」と明記されているか）
  • 人間による最終確認：検算役はAI同士の相互点検にすぎません。別セッションの点検を通った成果物は、必ず部署の人間の責任者が一次資料と突き合わせて最終確認します。AIの点検だけで稟議箱に上げることは憲法で禁止します。
  • 内部監査室：独立したフォルダとCLAUDE.mdを持ち、週1回、全室の成果物と記録を横断で点検して、理事長だけに報告します。他室の指示を受けない設計にします。
  • 稟議：検算・監査を通った成果物は「00_稟議箱」に集まり、理事長が本文を確認して承認したものだけが外に出ます。承認前の自動送信は憲法で禁止します。

5ナレッジ基盤の育て方 ― 選別し、承認し、版で管理する

理事長がこの1.5か月で積み上げられた実践（判断軸18件・791ファイル）は、この組織の大きな資産です。ただし、これらを自動的にナレッジとして取り込むことはしません。AIの生成物には誤りや古い情報が混じり得るため、そのまま基盤に入れると誤りが組織全体に配られてしまいます。

ナレッジに入れるものは、次の4段階を通します。

段階内容担当
① 選別791ファイルの全部ではなく、「型になったもの」「繰り返し使えるもの」だけを候補として抜き出す各部署の担当者
② 承認一次資料と突き合わせ、現時点で正しいことを確認したうえでナレッジ入りを承認する人間の責任者
（最終承認は理事長）
③ 版管理承認日・出典・適用日・承認者を記録し、v1・v2…と版を付けて98_ナレッジに置く各部署の担当者
④ 廃止管理制度改正などで古くなったものは削除ではなく「廃止」として日付を入れて分離する（過去の判断の根拠は残す）人間の責任者

判断軸18件も同じ扱いとし、承認を経たものだけを憲法から参照します。未承認のものは「候補」フォルダに置き、参照対象にしません。

この形にすると、組織が育つ仕組みは「AIが使うほど勝手に賢くなる」のではなく、承認済みナレッジ基盤が、人間の承認を通って一段ずつ厚くなっていくという形になります。基盤が厚くなった領域から次の部署を立ち上げる。これがこの組織の成長の実体です。

6段階ロードマップ

第0段階：土台（大部分は完了済みです）
  • 法人管理のアカウント整備 … 済（マニュアルで方針確定）
  • 憲法・番人箱・符号化の線引き … 済（法人版マニュアルv3）
  • 配布前研修の設計 … 済（v3に反映）
  • 残り：符号台帳の本番移行、furusato-aiフォルダの初期設置、AIサービス条件の6点確認（契約・学習利用・保存期間・権限・ログ・削除方法）の記録化
第1段階：3部署の試作とサンプル検証（目安：1〜3か月目）

構想の「戦略室とコンプライアンス室を先発に」というお考えに賛成です。立ち上げの順序は、本提案書・当日スライド・ご連絡のいずれも次の順で統一します。

順序部署役割着手
①加算戦略部（攻め）加算シナリオの試算・投資対効果の起案8月24日
②加算要件管理部（守り）取得加算の要件維持点検・算定根拠の記録整備9月29日
③外部環境分析部制度動向・報酬改定の一次情報ウォッチ（週報）10月26日

この3部署を先発とする理由は3つです。効果が金額で見えること（加算・返還は円で測れます）。返還・減算リスクに直撃すること（守りの失点防止が先）。そして扱う情報のほとんどが公開情報＋符号化済みデータで、番人箱に触れにくいこと（最初の1室として安全に練習できます）。

この段階は「試作とサンプル検証」であり、本番運用ではありません。各部署の1本目の成果物は実際の申請・届出には用いず、サンプルとして次の3点を検証するために作ります。

  1. 役割定義書の9項目が、その部署の実務に合っているか
  2. 検算役の5項目と人間の最終確認が、実際に誤りを拾えるか
  3. 成果物の型（出典URL・適用日・作成日・作成者）が、後から検証できる形になっているか
完了の目安：3部署それぞれでサンプル成果物が1本、検算役の点検と人間の最終確認を通って稟議箱に届き、役割定義書の修正まで終わった状態
第2段階：統制ラインの本稼働（目安：2〜3か月目）

内部監査室を立ち上げ、週次の横断監査と理事長直結報告を回します。ここまでで「攻め・守り・監査・決裁」の最小の組織が完成します。

完了の目安：監査報告が月4回、理事長に届いている状態
第3段階：残りの室を1室ずつ展開（目安：4か月目以降）

経営戦略部・財源開発部 → ブランディング室 → リスク管理室 → 人財室の順を目安とします。人事・評価・報酬部は最後です（番人箱に最も近く、構想資料でも検算役必須通過とされている部署のため、統制ラインが十分に枯れてから着手します）。

7動き出したときの1週間（イメージ）

曜日動き
月外部環境分析部が制度動向の週報を起案 → 検算役点検 → 稟議箱へ
火〜木加算戦略部が週報を受けて加算シナリオを試算／加算要件管理部が算定根拠の点検表を更新
金内部監査室が全成果物を横断点検 → 理事長へ直結報告。理事長は稟議箱を確認し、承認・差し戻し

※この表は3部署が揃った後の週次運用の流れであり、立ち上げの順序（①加算戦略部 → ②加算要件管理部 → ③外部環境分析部）とは別のものです。

理事長のお仕事は「稟議箱を開いて、承認するか差し戻すか」に集約されます。これが本部長＝理事長の全体監視の実装です。

8役割分担と進め方

役割担当
本部長（決裁・全体監視）北島理事長
運用（日次の実行・記録）岩永次長 ほか法人ご指名の方
設計・型の提供・立ち上げ研修一松
コンサルティング全体谷本社長

進め方は、現在のコンサルティングの訪問回に合わせて1回につき1部署、構成・役割定義・動かし方をご一緒に立ち上げる形をご提案します。私がお渡しするのは憲法・各部署の役割定義書（CLAUDE.md）・成果物テンプレート・検算チェックリストといった「型」で、実データの投入と日々の運用は、法人の皆様の手で行っていただきます。実データをお預かりしない形は、これまでのマニュアルと同じ整理です。

9むすび

構想資料の結びにあった「守りは失点を防ぎ、攻めで2040年を越える」という一文が、この組織のすべてだと受け止めております。本提案は、その一文を毎週の運用に落とすためのものです。

まずは第0段階の残り（符号台帳の本番移行・フォルダ初期設置・AIサービス条件の6点確認）と、第1段階の試作から。最初の一歩は本番運用ではなく、サンプルでの検証です。そこで役割定義書と検算の型を確かめ、確かめられた型だけを本番に上げてまいります。
